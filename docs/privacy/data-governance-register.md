## Register rules

Every future data category must be added here before Production enablement when it:
- introduces a new personal/business data field;
- creates a new public intake;
- creates a new document or financial-proof class;
- writes a new browser-storage key or cookie;
- sends data to a new external vendor;
- changes who can access an existing class;
- changes retention, deletion, anonymization or backup behavior.

For any row with \`TBD\`, engineering must not invent an automated destructive retention job.

For immutable financial/legal/audit rows, “delete user” must never mean a blind cascade. Apply the category-specific lifecycle decision and preserve referential/accountability constraints.
