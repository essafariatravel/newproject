# Traveller Hub — Phase II-D isolated Preview
Base Production 75411247, Phase II-C not merged. No migrations. The existing applicants table is dossier-scoped, so the directory projects exact matching declared passport + nationality + normalized name + DOB when present, never physically merges. Missing/invalid passport remains one record. Homonyms are separately displayed. No stable cross-renewal identity without an approved model.
Agency scope from authenticated active user, explicit agency join in all reads; no agency ID from browser. Exclude draft cases. Document attribution by applicant ID or sole-applicant case. Limit 100 cases/documents and 10 candidates; search/pagination server-side. Reuse only accepted current passport with SHA, 7 months validity, no open request, matching source and explicit selection; existing authenticated audited download and upload pipeline. No auto-reuse bank/photo/visa decisions. New requests may optionally save declared passport number/expiry to existing columns. No visa expiry invention. No reminder delivery; directory expiry filter only.
Qualification: synthetic assertions at protected Preview build, no database changes. Browser, runtime query and tenant isolation integration must still be verified before Production. No privileged mode.

## Review 2 — business workflow and authorization hardening
Restore legacy directory outside exact II-D Preview. Reuse endpoint rechecks source membership, accepted/latest/valid passport and permissions immediately before existing audited download. Unknown nationality never silently defaults. Mandatory seven months from application date in wizard/API/atomic transaction, shared DatePicker, optional passport number. Reused file objects removed when identity edited. Older source records accessible within bounded history. No storage keys or hashes emitted to UI.

## Review 3 — real data shape, inline discovery and operational UX
Confirmed Preview schema has existing passport fields and 90 historical rows (57 nonempty passport numbers, 6 expiry values, 17 agencies at inspection). Exact scoped CTE executed as aggregate in read-only SQL; no individual records exposed. Inline POST search keeps current programme selection and avoids placing search text in URL in the wizard. Selecting a different source requires confirmation before clearing selected files. Invalid/unavailable states are explicit. The directory itself retains its ordinary URL-based search. Browser sessions, actual reuse, submission, RTL/mobile and cross-agency endpoint tests remain release gates; no claim of complete qualification.

## R04–R06 — persistent profiles, expanded reuse, and renewal reminders
Additive Preview-only DDL in phase2d-preview-profiles.sql, never invoked at build time. Historical dossier records preserved; only exact corroborated historical matches can share a profile. Agency can create/edit independent profiles; linkage to new submissions is atomic and audited. Accepted, current, integrity-verified documents can be manually reused under internal upload-age limits (photo 180 days, marriage 90, bank/employment/travel 30); travel-specific pieces require same programme and explicit confirmation of travel details. Expiry is not inferred from upload date. Decision documents and unknown types excluded. Owner notifications inserted atomically on authenticated portal access or existing notification polling, one scan per hour, at under seven months, 30 days and expiry. Dedup per owner/profile/date/stage, current-stage action projection; no email, external push or offline scheduler. Shared Preview schema is additive; Production unchanged.
