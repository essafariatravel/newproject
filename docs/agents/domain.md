# Domain documents

This repository has one application context. Before domain exploration, read the root `GLOSSARY.md` if present and relevant decisions under `docs/adr/`. If either is absent, proceed; create terminology or decisions only when work actually resolves them.

Use the glossary's existing vocabulary in specifications, tests and reviews. If a proposed change conflicts with an ADR, identify the conflict before implementation.

Layout: root `GLOSSARY.md`; repository-wide ADRs in `docs/adr/`. A `GLOSSARY-MAP.md` would indicate a future move to multiple contexts; no such move is required for this application.
