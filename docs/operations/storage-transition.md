# Private document Storage transition — pending qualification

`src/lib/storage.ts` already supplies DB and Supabase implementations. Do not add a second provider. DB remains the default; a global provider switch does not migrate existing objects.

The local provider tests cover real HTTP round trips through a loopback substitute: immutable puts, byte identity, bounded downloads, explicit missing-key handling, denied permissions, HTTP failures, timeouts and redirect rejection. A failed delete now throws; only a verified missing object is idempotent success. This does not certify hosted bucket permissions or tenant authorization.

## Gates before hosted qualification

Identify the exact isolated project, private bucket and server secret scope. Current endpoint pinning intentionally does not authorize a new Supabase project. A new pin/bucket/env and Preview deployment need their own reviewed change. Verify `public=false`, no anonymous direct read/list/write, no broad authenticated policies, bounded MIME/size and server-only credentials. Custom ESSAFARIA sessions are not Supabase Auth JWTs; do not invent an `auth.uid()` tenant mapping. The service-role key bypasses RLS, so every application route must enforce its current DB-backed agency authorization before requesting an object.

Use synthetic files and two authorized test tenants only, in serial smoke tests after explicit hosted approval. For each agency, exercise allowed upload/read/replacement and denied access to another agency's application/document IDs; verify staff RBAC, immutable original SHA and unchanged metadata on errors. Never show object bytes, filenames, credentials or signed URLs in public reports. Do not enable direct browser bucket access to make a test pass.

## Recoverable migration protocol

1. Obtain the exact encrypted database and object recovery set; restore it on an isolated target. Inventory all storage references, including application documents, registration documents, top-up proofs and logos. Classify shared keys, absent bodies and unreferenced blobs; never infer successful coverage from counts alone.
2. Build a private encrypted manifest with opaque IDs, source/destination provider and key, MIME, length, SHA-256, source snapshot identity, phase and verified timestamp. Keep the source DB bytes and backups intact. Freeze affected writes or use a qualified per-document locking/version protocol.
3. Copy in bounded batches to a separately qualified private bucket, with immutable destination keys and no upsert. Download each destination through the intended provider, compare length, MIME and SHA-256 before recording `VERIFIED`. A conflict is acceptable only after the existing destination bytes match; otherwise stop.
4. A checkpoint is durable only after the verified manifest is committed. Restart skips only records whose source identity and destination SHA still match. Test interruption after upload/before checkpoint and after checkpoint/before reference switch. Never infer success from an HTTP acknowledgment alone.
5. Switch metadata only after every live reference is covered, with transaction locks, expected source version/hash checks and a single reviewed routing policy. There is currently no per-document provider column; therefore do not switch `STORAGE_PROVIDER` with an incomplete population. Validate every reference again after the controlled switch.
6. Rollback before source retirement restores the previous routing and metadata from the verified manifest; source bytes remain present. No source blob deletion is part of this preparation. Later retirement requires a new recovery point, full coverage and distinct authorization.

## Explicit release blockers

### Local durable recovery qualification (18 October 2026)

`src/lib/storage-operations.ts` supplies the journal used by the existing provider under the explicit `STORAGE_OPERATIONS_ENABLED=local-qualification` gate. It is now connected to document upload/resubmission/deletion, final decisions, initial registrations/follow-up, visa-request submission, top-up proof and external logos. Metadata adoption and deletion intent use the caller's actual Drizzle/pg transaction. Default DB paths remain unchanged. `migrations/proposals/0036_storage_operations.sql` remains outside automatic root discovery and the 0034/0035 candidate set; no approved release range is extended.

Disposable PostgreSQL tests exercise reserve-before-upload, verified byte/MIME/SHA identity, atomic metadata adoption and detachment, immutable object identity, restart with the same durable journal, retry after transport/audit failure, competing workers and immutable deletion receipts. Merely reserved or uncertain uploads cannot be queued for deletion: a reservation does not establish ownership of pre-existing bytes. An acknowledged delete is insufficient; a subsequent verified missing-object response is required. Bounded adapter timeouts preserve pending/uncertain state and do not claim cancellation of the external operation.

Qualification now includes real Next.js HTTP Server Actions, authenticated agency sessions, actual PostgreSQL and the existing provider talking to a loopback object server. Twenty complete checks cover wizard creation/financial debit, upload/read, denied cross-tenant read/replace/delete, replacement, lost ACK, actual transport timeout/retry, failed/successful delete, process restart, reconciliation, legal hold and concurrent document/wallet requests. Additional service integration tests exercise registrations/follow-up, top-up proof and logo replacement. Separate protocol/HTTP regressions remain relevant. This is not a deployed bucket/RLS qualification or a 500-user throughput claim.

The application factory binds the actual existing provider to the recorded loopback origin/bucket. It refuses deployed metadata, non-loopback targets, a changed binding or a non-public/non-disposable DB. Upload acknowledgments are persisted before verification. After interruption, an acknowledged upload can be verified and resumed; an unacknowledged create remains protected even if matching bytes are found, because ownership is not proven. Reconciliation is a bounded internal function, not a public cleanup endpoint or scheduler. The journal's global/table locks deliberately favor correctness and still require a separate concurrency design/qualification before hosted activation. No local test authorizes a hosted flag or provider pin.

Compensation callers retain pending/uncertain journal evidence when cleanup cannot finish. Draft deletion queues the physical operation atomically with metadata removal and reports pending verification on failure; it does not emit a completed physical-deletion event. Only verified absence creates the immutable journal receipt. Legacy objects without a journal ownership proof are preserved and require a reviewed migration/reconciliation, including old logos. Pending request wizard bytes remain transactional temporary DB staging and are removed on successful submission; they are not a second external provider.

External J+120 retention is now qualified locally with the same provider and journal, in addition to the DB path. `document_retention_jobs` in proposal 0036 stores the immutable reviewed intent before metadata detachment and physical deletion. Pending jobs block new uploads, metadata adoption and case status/decision changes. The service checks genuine final-decision audit/history, the exact J+120 anniversary, current exception review/holds, schema fingerprint, staging/shared copies and all owned objects. Batches are currently bounded to 100 objects per dossier; an unproven or larger inventory is blocked intact, never truncated into a successful receipt. All six supported document formats use the existing signature validator; official decision proof remains PDF/JPEG/PNG only.

`GET/POST /api/admin/document-retention` exposes dry-run and reviewed execution only behind the explicit `DOCUMENT_RETENTION_ENABLED=local-qualification` disposable-target gate, authenticated SUPER_ADMIN, strict POST Origin, bounded body and per-user rate limits. This is a local operator endpoint, not a hosted rollout or scheduler. Actual Next/HTTP/PostgreSQL tests prove denied tenant access/CSRF, PENDING on failed DELETE, restart/resume, hold protection, concurrent attempts with one global receipt and actual byte absence. Existing route/session/MFA protections remain active. Password-only sessions are never represented as MFA verified.

Only verified absence of every intended object creates the immutable global retention receipt and successful purge audit. Transport timeout, false DELETE acknowledgment or failed final audit leave durable PENDING state. A new hold or revoked coverage/policy stops remaining work; it cannot recreate bytes deleted before that hold. Physical deletion cannot be rolled back with SQL. Restored bytes behind a completed receipt trigger reconciliation rather than new deletion authority. Backup expiry and restore reconciliation must honor holds and existing receipts.

The changed-path local performance campaign uses six genuinely authenticated role actors, 500 synthetic agencies and 1,000 drafts. Its measured concurrency is request concurrency, not a count of distinct users or a cloud-capacity certification. Same-actor in-flight request submissions are coalesced to avoid redundant uploads, with each waiter's credential version and current authorization rechecked; DB idempotency/financial constraints remain authoritative across processes. The journal's serial protocol remains an explicit throughput limitation and is not silently weakened to pass a performance gate. Keep observed STOP results with the evidence and require the final measured budgets before any scale claim.

No Storage migration, bucket policy edit, hosted purge or provider switch has been performed.
